## Acceptance

- Launch is Linux-only, requires a controlling TTY, and emits only the clean
  URL/non-secret instructions. The rustix termios guard restores echo across
  every specified exit/signal path; non-TTY/non-echo failures stop before bind.
- Exact bootstrap and session state machines, entropy, TTLs, one-attempt/one-
  exchange behavior, monotonic deadlines, fixed-work comparison, instance and
  workspace binding, explicit revoke, and fail-closed lost-response behavior
  match the approved contract.
- Browser code contains no fragment/query reader, Web Storage, IndexedDB,
  cookie, service worker, credential logging, or browser-launch path. Session
  authority exists only in the current closure and authenticated header.
- Tower tests cover malformed/duplicate requests, mismatch, no TTY, expiry,
  a long-poll exchange that releases nothing before confirmation, deterministic
  concurrent winner, lost response, replay, deadline equality, terminal EOF,
  cross-instance/workspace, session expiry/revoke, Host/Origin/content type,
  and zero protected work/signature/decision on every auth failure.
- One mutation lease spans final session validation, fresh registry/governance
  load, actionability reload, key access, signing, and durable persistence.
  Deterministic revoke/expiry races and review-to-POST registry drift prove
  exactly one outcome and zero unauthorized signature/decision.
- Existing approval UI tests still prove exact arguments, required Human,
  approve/deny, double-submit rejection, unchanged v1/v2 actionability, and no
  automatic execution or generic live-v2 resume.
- Process tests prove stdout/stderr and argv contain no bootstrap/session value.
- `rtk cargo fmt --check -p proof-transport-cli` passes.
- `rtk cargo test -p proof-transport-cli` passes in the required host context;
  focused failures are not waived by broader counts.
- `rtk scripts/test-scoped.sh proof-transport-cli --list` is recorded for the
  integration owner; no provider environment variable is required or read.
