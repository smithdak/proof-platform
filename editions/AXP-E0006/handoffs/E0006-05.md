# E0006-05 Handoff

Status: complete

## Result

Implemented the D-E0006-015-authorized current-document bootstrap/session
delivery remediation without changing the frozen approval-console contract,
digest, TTLs, public routes, response shapes, or one-session semantics.

The failure was a split linearization across three independently scheduled
steps. A browser exchange could claim a pending bootstrap, terminal
verification could validly transition it to `Verified` before the bootstrap
deadline, and the admitted exchange task could resume only at or after the
deadline. The old delivery loop then expired that already verified bootstrap
instead of activating the session. This is sufficient for one current browser
document to produce terminal `Local confirmation verified.` followed by the
browser's generic exchange rejection; it does not require a second browser or
exchange.

The remediation completes `Pending -> Verified -> Exchanged` and session
activation under the same authority lock when terminal verification observes
an already claimed exchange. The original admitted exchange remains the only
delivery path. Conversely, an exchange that first claims an unclaimed
`Verified` bootstrap activates the session atomically under that lock. The
delivery loop checks session expiry before releasing the secret, so a delayed
response still cannot outlive the frozen idle or absolute session TTL.

The suggested Tokio pre-poll lost-wakeup hypothesis was assessed and
deterministically falsified for the repository's locked Tokio 1.52.3. A
`Notified` future snapshots the `notify_waiters` generation when constructed,
and first poll observes an intervening broadcast. A regression constructs the
future, broadcasts before first poll, then proves the await completes without
yield-based timing.

## Deterministic evidence

The regression uses explicit `claimed` and `release` barriers, not task yields
or wall-clock races. It proves all of the following:

- the first exchange has completed its unique claim before verification;
- a concurrent duplicate exchange loses;
- verification at second 119 commits the exchange and active session;
- delaying the original delivery task to the exact 120-second bootstrap
  boundary does not undo that committed exchange;
- the original exchange receives the active session and replay fails;
- delaying delivery to the exact 300-second idle boundary still expires the
  session and returns no secret;
- `notify_waiters` between `notified()` construction and first poll is observed
  by the locked Tokio implementation.

Existing deterministic coverage continues to close reload/navigation,
lost-response, duplicate registration, concurrent loser, replay, wrong-code,
bootstrap equality-expiry, idle equality-expiry, absolute expiry, revoke, and
wrong-scope paths. Generic browser error behavior and auth ordering are
unchanged.
