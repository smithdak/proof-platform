## Independent source diagnosis

The pre-remediation implementation split the successful exchange across three
independently scheduled steps:

1. `exchange` claimed the one pending bootstrap and released the authority
   lock;
2. `verify_terminal` could validate the exact code before the 120-second
   deadline and store `Verified`; and
3. only when the admitted exchange task resumed did the old loop attempt to
   activate a session.

That old loop called bootstrap expiry before activation. Under the exact
controlled schedule claim → verification at second 119 → delivery resumption
at second 120, `Verified` became `Expired` and the admitted exchange returned
no session. This directly explains `Local confirmation verified.` followed by
generic browser rejection without requiring another browser or exchange.

The candidate closes that split linearization under the existing authority
lock:

- if terminal verification sees the one already-claimed pending exchange, it
  atomically activates the session and commits bootstrap `Exchanged`;
- if the exchange first sees an unclaimed in-time `Verified` bootstrap, that
  one exchange atomically claims and activates it;
- the claim bit still admits at most one exchange, and only the admitted
  exchange function can return the secret; and
- the delivery loop expires the active session before reading its secret, so
  delayed delivery at idle or absolute equality returns no authority.

Randomness failure revokes authority. A cancelled/lost delivery after claim may
leave consumed, undisclosed in-memory authority until expiry or shutdown, but
no replay can retrieve it; this is the frozen lost-response behavior.
