## Verified intent behavior

- Initial actions are explicit `Sign denial` and `Sign approval` buttons. The
  approval action no longer uses success styling; it uses the red danger
  treatment. Initial clicks only construct intent and cannot call the decision
  endpoint.
- The final action lives in a labeled in-document `role="region"` with an
  accessible heading/instruction relationship, exact visible outcome,
  operation/version, request ID, challenge label, focus transfer to the input,
  visible focus styling, and cancel focus restoration.
- The case-sensitive challenge is constructed only as
  `DENY <request-id>` or `APPROVE <request-id>` from the frozen outcome and
  request. The final button begins disabled and strict string equality is
  required. All buttons are `type="button"`; there is no form or submit
  handler, and Enter is suppressed on both challenge input and final action.
- One `Object.freeze` snapshot captures request, outcome, operation/version,
  approver, and reason as primitive values. Inbox selection and approver/reason
  controls remain disabled while intent, preflight, or submission is pending.
  Programmatic/current-state mismatches also keep final submission disabled.
- Final submission performs a fresh protected detail GET before the unchanged
  decision POST. It rechecks object identity, selected request,
  operation/version, actionability, request deadline, enrolled approver, and
  unchanged form values, then sends only the frozen request, outcome, approver,
  and reason.
- Cancel, request disappearance, expiry, actionability/operation change,
  selection/detail/inbox failure, End Session, protected preflight failure, or
  page reload/session-memory loss clears the in-memory intent without a known
  decision POST. Cancel and End Session remain available during preflight, so
  either can invalidate the captured object before the asynchronous GET can
  proceed to POST.
- After decision POST starts, failures are not reported as known no-send
  outcomes. The UI reports the result as uncertain and directs the Human to
  review the inbox before another action. The backend authority lease remains
  decisive for races after browser preflight.
- Native `confirm()` and form submission are absent. Static scans also found no
  local/session storage, cookie, or IndexedDB persistence path; intent exists
  only in the current JavaScript closure.
