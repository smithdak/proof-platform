## Audit repair — preview containment and strict persisted records

The independent audit identified lexical-only preview containment and permissive
persisted Edition/Object decoding. The repair remains entirely in
`crates/proof-content/**` and this handoff.

- Linux preview writes and reads now walk `.proof`, `data`, `previews`, the
  validated edition directory, and the artifact leaf via descriptor-relative
  `openat` with `O_NOFOLLOW`; missing write-side directories are made one
  component at a time with `mkdirat` and immediately re-opened no-follow.
  Existing leaves must be regular files opened no-follow. A pre-existing
  symlink in any preview component or leaf fails before it can be followed.
- Creation remains `O_CREAT|O_EXCL|O_NOFOLLOW`; canonical bytes are synced and
  atomically linked no-overwrite. The link source is the still-open temporary
  file through `/proc/self/fd/<fd>` with `AT_SYMLINK_FOLLOW`, preventing a
  source-name replacement race. A final-name race reopens the final leaf
  no-follow and only accepts equal bytes. Any failed partial temporary remains
  as evidence. Non-Linux builds fail closed rather than use a weaker path API.
- Persisted edition reads now use the same descriptor-relative no-follow walk
  through `.proof/data/editions/<edition_id>.json`; symlinked components or a
  symlink/non-regular edition leaf fail before any bytes are consumed.
- Before deserializing an edition for manifest construction, a Content-local
  raw-value validator rejects unknown keys on the complete edition and every
  complete object. Shared `Edition`/`Object` serde behavior was not changed.
- Request parsing now explicitly requires lowercase hyphenated UUID spellings
  (and UUIDv7 for the idempotency/publication ID), matching the frozen schema;
  uppercase and simple UUID spellings are rejected before preview I/O.
- Added Unix symlink directory/final-file escape tests for both publication and
  independent verification, unequal-existing file coverage, Edition/Object
  unknown-field tamper tests, UUID spelling tests, and version-label/manifest
  tamper verification. The pre-existing simulated
  replay-completion crash test still demonstrates preserved one-artifact
  evidence and an in-progress claim.
- A Content-local unit seam injects a real post-write sync failure. Its test
  proves the temporary file remains, the final leaf is absent, and a later
  successful retry creates the final leaf without deleting the preserved
  temporary evidence.

## Artifact schema, path, and lifecycle

- The handler reads the requested persisted edition, recomputes each complete
  object SHA-256 digest, recomputes the sorted-object edition digest, builds
  `proof-content-preview-manifest/v1`, and rejects a mismatched requested
  manifest digest before writing.
- It emits canonical compact UTF-8 JSON for
  `proof-content-preview-artifact/v1` at the only allowed relative path:
  `.proof/data/previews/<edition_id>/<idempotency_key>.json`.
- The artifact binds the v2 request, kernel operation-input digest, full
  manifest, context timestamp, and actor. Its external digest is the kernel
  Generic digest of the frozen artifact-digest envelope; the operation output
  binds that digest/path and the original engine proof signs the output.
- Publication creates a same-directory temporary file with `create_new`, syncs
  it, and atomically hard-links it to the final path (no overwrite). Existing
  equal bytes are not rewritten; unequal bytes, partial-write, and boundary
  errors fail closed. Failed temporary files are preserved; no cleanup occurs.
- `verify_preview_publication` independently checks canonical artifact bytes,
  safe path, recomputed edition/manifest/input/output/artifact digests, and
  the original proof signature/bindings. `verify_preview_approval_execution`
  also validates the signed approval binding and original proof/output/timing.

## Verifier extension — artifact file integrity

- `verify_preview_publication(workspace_path, input, outcome, signing_principal)`
  retains the same public signature and now also re-opens the exact edition
  preview directory through the no-follow descriptor walk. It requires exactly
  one final entry: the expected `<idempotency_key>.json`, opened again as a
  regular no-follow file. Additional final artifacts, arbitrary entries,
  symlinks, and non-regular entries fail closed.
- Temporary evidence is accepted only when its name exactly matches the
  publisher's producer format for this final artifact:
  `.<expected-idempotency-key>.json.<lowercase-hyphenated-UUIDv7>.tmp`.
  It is regular-only and does not count as success. Other idempotency keys,
  malformed/noncanonical/non-v7 IDs, symlinks, non-regular temporary entries,
  and all other entries fail closed.
- Regression coverage exercises the valid one-artifact case, producer-shaped
  temporary evidence, malformed/cross-key/non-v7/uppercase temporary names,
  extra final JSON, non-regular entry, and Unix symlink entry cases. The
  injected sync-failure retry test also verifies its actual preserved temporary
  evidence through the integrity helper. Runtime can use this unchanged verifier
  API for the frozen `artifact_file_integrity` check without a new cross-crate
  contract.

## Replay, mutation, proof, and tamper evidence

- First signed-approved v2 execution writes one artifact and returns the
  engine-generated `release.publish::v2` proof. Exact retry returns equal
  output, proof ID, and signature without a second file.
- Changed input with the same tuple returns the kernel conflict before the
  handler/mutation. A bad manifest produces a failed claim; retry is
  indeterminate and creates no preview directory. A simulated replay-complete
  crash after artifact publication leaves one artifact and a claimed/in-progress
  tuple; it never executes again.
- Tests tamper artifact bytes, output environment, and proof operation; each
  fails independent verification. The first-execution test also verifies the
  constructed signed approval execution against the original outcome.

## Residual risks and cross-owner requests

- The engine intentionally cannot make the domain artifact and replay-proof
  completion one transaction. A crash after publication remains a preserved,
  blocked claim, exactly as the frozen fail-closed recovery policy requires.
- Content verifies artifact/proof/approval data supplied to its public
  verifier. Runtime/CLI remain responsible for durable replay-ledger inspection
  (including completed/claimed/failed state), loading/enforcing the exact
  delegation scope, live checkpoint/evaluation binding, and passing the
  original `ExecutionOutcome`; no cross-owner API is invented or requested.
- The local preview boundary is only exercised in disposable test workspaces.
  No live journey, external effect, or credential handling has occurred.
