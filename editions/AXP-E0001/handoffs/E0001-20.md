## Findings

Final pre-provider audit found that exact `live-start` argv was replayable into
a second paid run, follow-up commands could omit the selected workspace,
direct CLI approval could persist a decision by the wrong enrolled Human
before runtime rejection, the advertised review path did not expose the five
exact arguments, and the live-v2 operator procedure was missing. After the
atomic start repair, fault injection found one additional availability gap: a
process death after the atomic claim but before provider preparation preserved
the sole run safely but left it unable to advance. The post-commit concurrency
audit then produced a concrete stale-resumer schedule: epoch A advanced to a
Prepared attempt, epoch B appended a different Prepared attempt from its stale
snapshot, and the second immutable checkpoint made all later recovery invalid.
Without an execution lease, takeover after A's durable Dispatching barrier
could also terminalize the run immediately before A sent, orphaning one paid
response even though duplicate send remained impossible.

## Repair and invariants

- Kernel now defines a backward-compatible `LiveRunStartClaim` and
  Acquired/Existing/Conflict/Unsupported result. Recording storage and SQLite
  implement the same four-record claim contract.
- SQLite migration 13 adds the claim ledger. `BEGIN IMMEDIATE` atomically
  commits the canonical readiness/setup claim, initial Running session run,
  `agent_runtime_v2` checkpoint zero, and Started event zero. Exact replay
  revalidates claim JSON, immutable initial records and digests/indexed
  columns, plus progressed run identity before returning the original run.
- Runtime derives stable claim digests from the exact start intent and sealed
  setup without using the proposed run ID or process epoch. Acquired starts
  reread the four records before preparation; Existing returns
  `AlreadyStarted` before gateway construction; conflicts and unsupported
  stores fail before the provider boundary.
- Pristine same-run recovery requires a globally new persisted epoch, exact
  revision-one run chronology and goal, the exact initial state and Started
  event, epoch-only checkpoints, zero attempts/counters/usage/cost, and no
  steps, bound approvals, evaluations, or later events. An injected crash
  after claim resumes the original run to approval with one dispatch. Prepared
  attempts remain certified pre-send; Dispatching/ResponseReceived restarts
  remain ambiguous and provider-free.
- `AgentRunStore` now has a default-compatible expected-tail checkpoint append
  contract. Recording storage decides under its mutex; SQLite uses
  `BEGIN IMMEDIATE`. Both exact-validate candidates, current evidence, and
  exact-retry predecessors; displaced writers return `Stale` with no insert,
  malformed or corrupt evidence errors, and exact current retries are
  idempotent.
- Runtime holds a crash-released workspace execution lease from before every
  resume read through return, and from a newly acquired start claim through
  return. Resume contention returns `LiveRunBusy` with zero writes, while
  start contention may retain exactly the atomic claim/run/checkpoint-zero/
  Started-zero bundle. Both paths perform zero gateway construction, provider
  sends, or governed effects, and the start path performs no post-claim write.
  Every later checkpoint prevalidates its prospective complete history and
  uses expected-tail append; resume epochs bind the exact prior state and
  ordinary saves reject a different persisted epoch.
- Live CLI output emits array-form workspace-bound review, exact-Human
  approve/deny, policy-bearing live-resume, and watch argv as applicable.
  Approval persistence independently binds the native v2 history, exact five
  arguments, signed request, waiting step, input digest, and sealed Human.
  Generic resume and approval UI are not advertised.
- `docs/dogfood/release-manager-live.md` is the secure persisted-argv operator
  and independent-verification procedure. The historical preview provider gate
  is explicitly superseded for E0001 live-v2.
