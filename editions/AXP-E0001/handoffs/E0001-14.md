## Finding and repair

`cmd_delegation_grant` previously persisted the workspace issuer as `Human`
through an `ON CONFLICT` update. With a distinct recipient, that left the
workspace Agent reclassified; the same update could turn an enrolled Human
recipient into an Agent. Same-actor tests masked the issuer defect because the
second recipient upsert changed the row back to Agent.

The command now saves `principal_from_keypair(&ws.keypair)` through storage's
canonical immutable principal API. The recipient compatibility helper queries
the existing kind/key inside one immediate transaction, accepts only an equal
kind and any supplied key, and inserts only when absent. It has no
conflict-update branch. A collision returns a specific error before
`save_delegation`.

Two regressions prove that a grant to a distinct recipient preserves the
workspace Agent ID/kind/key and that a pre-enrolled Human recipient remains
unchanged while the delegation table remains empty. Existing complete and
legacy scope round trips pass in the same five-test module.
