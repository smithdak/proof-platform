## Changed files

- `crates/proof-kernel/src/executor/store.rs`
  - Added the default-compatible public handler hooks:

    ```rust
    fn idempotency_policy_for(&self, version: &str) -> IdempotencyPolicy {
        self.idempotency_policy()
    }

    fn execute_versioned(
        &self,
        version: &str,
        input: &Value,
        context: &ExecutionContext,
    ) -> Result<Value, ExecutionError> {
        self.execute(input, context)
    }
    ```

  - Added direct compatibility assertions showing an unchanged legacy handler
    retains `IdempotencyPolicy::None` and its existing `execute` result through
    the defaults.
- `crates/proof-kernel/src/executor/engine.rs`
  - Routes replay selection through `idempotency_policy_for(version)`.
  - Routes handler entry through `execute_versioned(version, input, context)`.
  - When execution storage is present and `delegation_id` is explicit, requires
    the loaded row to have that ID, exactly match the corresponding chain
    grant, and name the executing actor as recipient before applying its
    operation/domain scope.
  - Retains the existing chain fallback when no store is configured and retains
    the existing chain-only path when no explicit ID is supplied.
- `crates/proof-kernel/tests/versioned_execution.rs`
  - Adds focused version/replay/compatibility and loaded-authority coverage.

No shared field, error variant, proof shape, replay shape, registration key, or
transport/storage/content surface changed.

## Compatibility and behavior evidence

- Existing `OperationHandler` implementations remain source-compatible because
  both new methods have object-safe defaults delegating to the old methods.
- Existing handlers that override `idempotency_policy` continue to apply that
  policy through the default `idempotency_policy_for`; the existing exact-
  replay suite passes unchanged.
- Existing handlers that implement only `execute` continue to execute through
  the default `execute_versioned`; all existing kernel engine, benchmark,
  persistence, and replay tests pass unchanged.
- A single multi-version handler test proves:
  - `release.publish::v1` selects `None`, accepts input without an idempotency
    key, executes on each call, and produces distinct proofs;
  - `release.publish::v2` selects `RequiredUuidV7ExactReplay`, enters the handler
    once, and the second call returns the exact original output and proof; and
  - the requested version is observed by both version-aware hooks.
- Legacy chain-only callers and explicit-ID callers without configured storage
  remain supported. The E0001 live runtime must configure the durable store and
  require an explicit ID as frozen by the downstream contract.

## Preserved execution order

The engine still performs, in order: registry lookup; governance and signed
approval; lifecycle status; delegation validation and loaded scope; handler
lookup; version-aware replay-policy selection; replay input validation and
claim; benchmark gate; version-aware handler entry; proof creation; then replay
completion or ordinary context/proof persistence. Completed replay still exits
after authority and replay validation without handler or new-proof entry.

Authority failures are tested before both version-aware hook counters. Tests
cover missing stored ID, loaded/chain mismatch, wrong recipient, revoked row,
expired row, operation mismatch, and domain mismatch. The implementation uses
existing `Delegation`/`ScopeViolation` errors and adds no transport mapping.
