# E0001-10 Handoff

Result: owner-ready; the additive runtime-owned live-start check is implemented
and the complete scoped runtime suite passes 99 tests.

## Public API and validator reuse

- Added
  `AgentRuntime::check_live_start_setup(&LiveRunSetup) -> Result<(), AgentRuntimeError>`.
- The method accepts only `LiveRunIntent::Start`; Resume returns the specific
  `LiveSetup` error
  `check_live_start_setup accepts only LiveRunIntent::Start`.
- For Start it calls the existing authoritative `validate_live_setup` with the
  exact supplied goal and a prospective 300-second deadline, loads the exact
  target definition through `load_live_agent`, then calls the existing
  `validate_live_agent`. It introduces no duplicate validator.
- `run_live` Start now calls this public method before `start_live`.
  `start_live` still selects its actual timestamp and repeats setup,
  target-agent, goal, profile, and authority validation immediately before its
  first `AgentRun` write, preserving the authority-validity race closure.

## No-mutation and negative evidence

- A valid check is invoked twice and leaves an exact before/after snapshot
  unchanged. The snapshot covers agent definitions; runs; steps; checkpoints
  (including provider-attempt state); evaluations; events; approval requests;
  proofs; execution contexts; delegations; and every workspace path/file byte.
- An approval-store write spy separately proves zero approval request,
  decision, or execution writes. Gateway factory creates/contexts and gateway
  sends remain `0/0/0` for valid and invalid checks.
- Negative coverage rejects, before any mutation:
  - Resume intent and a missing target AgentDefinition;
  - an altered goal even when its claimed initial-input digest is recomputed;
  - wrong target provider, model, tool allowlist, or frozen limits;
  - forged deterministic preflight evidence;
  - each of the nine non-run binding inputs (preflight digest, agent,
    approver, delegation ID/digest, edition, manifest, idempotency key, and
    version label);
  - invalid process epoch, static tool-set digest, and authority validity that
    does not cover the prospective 300-second deadline.
- Existing runtime regressions continue covering the broader strict policy,
  delegation scope/chain, identity, approval, start/resume, replay, and live
  journey behavior through the same validators.
