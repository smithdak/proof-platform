## Delivered behavior

- Added the frozen command shapes:
  - `proof agent live-start <agent_id> --goal <goal> --policy-file <path>
    --preflight-evaluation-id <uuid> --delegation-id <uuid>`
  - `proof agent live-resume <run_id> --policy-file <path>`
- Added a strict CLI-local `operation_scope` DTO. Grant, save, load, list,
  validate, export, and import preserve exact operation/domain/resource scope;
  legacy scope stays explicitly unbounded and unknown nested fields fail.
- Live start independently reloads the named deterministic evaluation and its
  complete trace evidence, reruns `DeterministicTraceEvaluator` at the stored
  evaluation timestamp, and requires the exact ordered ten passed checks,
  10/10 score, evaluator, policy digest, trace digest, and claimed evaluation
  fields before live-policy or provider work.
- Live-policy setup requires canonical equality with the frozen template,
  verifies the exact ordered unique 17 checks and 20 tamper vectors, and
  independently computes the template, check-set, tamper-set, pricing,
  instructions, initial-input, parameters-schema, declaration, and tool-set
  digests.
- The synthetic goal, edition record, object keys/content digest, safe path,
  manifest digest, immutable agent profile, sole trusted human approver, and
  explicit UUIDv7 delegation are locally verified. Live authority is exactly
  the active singleton `release.publish`/`content` scope through the 300-second
  deadline; default, wildcard, structured-resource, extra, wrong, revoked,
  expired, not-yet-valid, short-lived, recipient-mismatched, and missing grants
  fail closed.
- Resume reloads the original run and `agent_runtime_v2` checkpoint, strictly
  decodes all twelve resolved bindings, independently re-verifies preflight,
  goal/edition/manifest, approver, exact delegation ID/digest/serialized grant
  and one-grant chain, then reconstructs the frozen policy with a fresh UUIDv7
  process epoch. Authority and policy IDs are not accepted from resume CLI
  arguments.
- The CLI-owned deferred gateway factory is credential-free to construct and
  register. Runtime invocation first validates frozen provider context, rejects
  any present `OPENAI_BASE_URL` before reading a key, then alone reads
  `OPENAI_API_KEY` and constructs the direct default-base OpenAI gateway. Errors
  do not include key/base-url values or private identity material.
- Missing-key integration evidence reaches the runtime dispatch boundary only
  after valid local setup: factory/base/key reads are `1/1/1`, while gateway
  construction and send remain `0/0`. Invalid preflight, policy, delegation,
  scope, checkpoint, or runtime policy evidence leaves factory/base/key/
  construction/send at `0/0/0/0/0`.
- Real-SQLite terminal tests prove both sealed Failed and sealed Succeeded/
  Completed replay are read-only. The successful no-network script performs an
  exact tool call, signed approval, process-epoch resume, `release.publish::v2`,
  exact terminal Finish, Succeeded storage, one Completed event, and 17/17
  evaluation. Replays return the identical outcome/evaluation while preserving
  checkpoint/event/evaluation rows, stored epoch, complete-trace digest, and
  zero factory/environment/construction/send activity.
