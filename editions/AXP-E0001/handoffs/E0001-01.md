## Frozen public and evidence shapes

The contract freezes the complete `release.publish::v2` RegistryEntry. It is
Content `v2`, action `content:release_publish`, human-only,
delegation-grant-authorized, required UUIDv7 idempotency, `content-release`
consequence, `operation-effect-v1` evidence, B1 benchmark, and active only after
Gate B implementation/activation. Null deprecation/replacement fields are
explicit.

The strict input has exactly five required fields: UUIDv7 idempotency key,
existing edition UUID, literal preview environment, validated version label,
and canonical SHA-256 manifest digest. The contract also freezes:

- canonical sorted preview manifest and recomputation rules;
- compact immutable no-overwrite artifact and safe relative path;
- output identity/artifact references and one original engine proof;
- proof actor/delegation/input/output/timestamp/signature binding;
- exact replay tuple `(release.publish, v2, idempotency_key)` and original
  output/proof replay;
- claimed/failed/crash boundaries with no automatic mutation retry; and
- rollback that preserves replay, attempt, approval, proof, artifact, and
  signed evidence.

## Authority, migration, and CLI prerequisites

The only valid live grant has an explicit SQLite ID, the agent recipient, a
matching chain entry, validity through the run deadline, no revocation, and
exact structured scope:

```json
{
  "allowed_operations": ["release.publish"],
  "allowed_domains": ["content"]
}
```

Migration v12 appends `delegations.scope_json TEXT NOT NULL DEFAULT '{}'`.
Storage uses a local `deny_unknown_fields` DTO: only operation/domain arrays
and optional `resource_scope` are valid general keys. Malformed or unknown-key
JSON fails load. `{}` is legacy-readable only; the E0001 exact grant requires
the two singleton arrays and forbids structured `resource_scope`. This does not
change the shared kernel deserializer. The down path removes only the v12
column, preserves legacy rows/columns, restores v11 while writers are
quiescent, and disables the live journey.

Wave ownership is explicit:

- K, `E0001-06` (`proof-kernel`): version-aware replay/execute hooks and explicit loaded-ID
  enforcement tests without narrowing legacy callers.
- S, `E0001-07` (`proof-storage`): migration v12, strict `load_delegation`, upgrade/down and
  scope round-trip/error/enforcement tests.
- W3 `E0001-02` (`proof-agent-runtime`): strict attempts/evaluator plus the
  public additive lazy-provider seam consumed by W4.
- W3 `E0001-03` (`proof-content`/registry): v2 artifact and exact replay.
- C, W4 `E0001-08` (`proof-transport-cli`), after W3+W2: exact grant/save/load

The CLI ordering test removes the API key and proves bad preflight/policy/

## Provider request and recovery

The provider contract is direct `POST https://api.openai.com/v1/responses`,
exact requested/returned model `gpt-5.6-sol`, `store=true`, no stream,
background, parallel tools, base-URL override, hosted tools, or failover. The
complete instructions are resent on continuation because the prior response's
instructions are not implicitly carried by `previous_response_id`.

The policy binds exact sealed instructions, resolved synthetic input, custom
function name/description/strict parameters, ordered one-element tool set,
request settings, and all component/request digests. Allowed outbound data is
only those sealed synthetic values and the canonical tool result. It prohibits
credentials, environment-variable values, repository/file/source content, secrets,
private keys, real/customer data, and unapproved network resources.

The policy is canonical for the byte-exact instructions and initial goal and
for canonical-JSON equality of the function declaration and structured
`function_call_output` continuation template. The continuation carries the
committed call ID and a canonical compact JSON string containing only
`ok=true`, the canonical governed output, and proof ID. The contract copies
these values exactly; digest tests compare them rather than paraphrases.

E0001-02 exports `LiveRunSetup`, `LiveRunIntent`, evidence/binding/authority
material, `ModelGatewayFactory`, its exact context, compatible
`new_with_gateway_factory`, and `run_live`. Existing `AgentRuntime::new` wraps
its supplied gateway in `FixedModelGatewayFactory`. Setup and factory
registration are credential-free. Runtime validates setup, creates or reloads
the run, resolves/recomputes evidence, persists and rereads the initial v2
checkpoint/event, persists/rereads a `prepared` attempt, and only then invokes
the factory. E0001-08's factory alone reads the key and builds the HTTP gateway.
Pre-secret failures assert zero factory and zero send invocations. A crash
before durable `dispatching` sends zero bytes; after it remains ambiguous.

Strict `agent_runtime_v2` persists authority, policy/preflight/tool/pricing
digests, exact provider configuration, process epoch, attempts, counters,
cumulative usage, nullable provider cost, calculated cost, final output, and
terminal error. Each strict `proof-provider-attempt/v1` persists requested
model/endpoint/cursor, exact request/tool declarations and digests, attempt and
process lineage, returned model/body/decision digests, usage, per-attempt and
cumulative provider/calculated cost, pricing identity, or one exact failure.

Recovery states are `prepared`, `dispatching`, `response_received`, `committed`,
`rejected_retryable`, `failed_retryable`, `failed_terminal`, and `ambiguous`.
Only certified-zero-byte local failure and explicit 429 rejection are eligible
for the single run-wide retry. Timeout, possible write, 5xx, partial/malformed
2xx, missing ID/usage, crash after dispatch, or response-persistence failure is
ambiguous: seal failed, never retry, never dispatch a tool.

Before any request byte, runtime increments dispatch count, commits the full
`dispatching` checkpoint, appends the matching immutable `model_requested`
event, and rereads/compares both. Fault injection and a send spy are required.

## Exact live policy

The machine policy rejects unknown fields and binds twelve live fields,
including preflight/delegation digests and process epoch. The immutable
preflight record rejects unknowns and contains only already-sealed deterministic
policy/trace/evaluation evidence. Digest chronology is acyclic.

The exact required live check IDs, in order, are:

Passing means exactly these 17 unique IDs, 17/17, score 10000, and the exact-
set digest. The exact ordered 20 tamper IDs are listed identically in contract
and policy; cardinality 20, uniqueness, exact order, and
`proof-release-manager-live-tamper-vector-set-digest/v1` are mandatory. The
digest is repeated in resolved policy, initial/resumed runtime evidence, and
final evaluation metrics.

## Limits and unknown cost

| Limit | Exact rule |
|---|---|
| provider dispatches | at most 4 |
| logical model turns | at most 3 |
| retries | at most 1 run-wide |
| tool attempts | at most 2, exactly 1 required to pass |
| successful preview mutations | exactly 1 to pass, never more than 1 |
| total tokens | at most 10,000 cumulative |
| output tokens/request | 1,024 |
| elapsed run time | 300 seconds including restart/approval |
| calculated-cost runtime limit | 120,000 micro-USD |
| owner authorization | 150,000 micro-USD for one primary run |

Pricing schedule `proof-openai-gpt-5.6-sol-pricing/2026-08-30` conservatively
charges every input token at 5 micro-USD and output token at 20 micro-USD. The
10,000-token worst mix with 4,096 output tokens is 111,440 micro-USD. Provider
cost may be null only with status `unavailable`, complete usage, and known
sealed calculated cost. Null never becomes zero. Missing/malformed usage,
unknown model/schedule, drift, overflow, or unknown/over-limit calculated cost
fails before tool dispatch.

## Residual risks

- Gate B and B5 spend approval are still pending; none of this proposed
  language is active or authorizes a request.
- K/S are W3 dependencies; runtime+Content+K/S are W4 CLI dependencies. They
  are real implementation work, not documentation-only work.
- Legacy delegation rows intentionally deserialize to unbounded `{}` and are
  incompatible with this live journey until explicitly re-granted.
- Crash after durable dispatch intent is conservatively ambiguous even if the
  remote service ultimately saw no bytes; availability is traded for safety.
- Provider invoice cost remains unavailable from the consumed response body;
  the sealed calculation is conservative evidence, not invoice reconciliation.
- API/model/pricing drift requires a new versioned Gate B decision; it cannot be
  patched silently into this policy.
- The public lazy-provider seam is proposed and unimplemented. E0001-02 must
  land it before E0001-08; W4 may consume but not redesign it.
- V12 rows with unknown scope keys will fail closed rather than silently lose
  data. Upgrade tests must surface any preexisting non-canonical row.
