## Finding and repair

Import previously opened the gzip/tar twice: once to read the first manifest
and again, after database/CAS writes, to extract workspace files. The file path
was reduced to three strings and joined beneath `.proof/data` without rejecting
`..`; a raw tar member such as `workspace-data/../keypair.json` therefore
escaped into the private control directory. Writes also followed a symlinked
data subdirectory or leaf. Finally, a workspace proof JSON file was not
required to match the already verified manifest proof, creating a later
re-ingestion path for unbound proof material.

Import now consumes one open archive stream, requires one regular manifest,
and fully preflights strict ordinary workspace-data components, entry types,
JSON names, and duplicate destinations before archive-specific persistence.
Manifest proof IDs must be unique; each proof file must have its exact ID name
and exact serialized manifest value. This removes both archive-swap ambiguity
and the unbound proof-file path.

Workspace JSON is published through securely opened descriptor-relative
directories. A `0600` same-directory temporary file is synced, atomically
renamed over the leaf, the directory is synced, and exact bytes are reread.
Renaming replaces a symlink/hard-link leaf itself rather than following its
external target, while a symlinked directory component fails closed.

## Bounded scope

Archive format remains v1. Cross-database/CAS/filesystem import is not one
transaction, and no new archive-size policy is asserted. The repair makes the
single archive snapshot, identity/proof preflight, and final workspace paths
fail closed; broader transactionality and global workspace JSON hardening stay
separately scoped.

No credential was read and no provider attempt, live v2 run, artifact,
failure, or charge was created.
