# E0001-17 Handoff

Result: implementation accepted; credential-free workspace identity binding,

## Finding and repair

Ordinary `Workspace::open` parsed the actor from `.proof/config.json` and
loaded the signing key independently without requiring their principal IDs to
match. Actor-bearing commands could therefore construct a proof naming one
principal while signing with another key. The descriptor-relative live
preparation path already rejected this mismatch, but the rest of the CLI did
not. Rotation likewise loaded only the key before archiving and mutating the
identity, so it could conceal a mismatched or partial state.

Initialization also truncated existing config and key files. Re-running
`proof init` could silently replace the active identity while retaining the
workspace's prior proofs, delegations, and data. Rotated-key archives used only
a millisecond timestamp and were opened with truncation, allowing a same-name
archive to replace history.

Ordinary open now hardens the config as a private regular file and applies the
same exact actor/key invariant as secure preparation. Rotation opens through
that invariant before creating an archive or changing any identity/storage
state. Initialization refuses when either identity leaf exists and creates new
identity files with `create_new`; rotated archives add a UUID and use the same
no-replace write. Config updates during an intentional rotation are synced and
retain mode `0600`.

## Bounded scope

This repair makes partial identity state fail closed; it does not add a
multi-file transaction or automatic recovery protocol for a process death
between config and key replacement during an intentional rotation. The
private old-key archive remains available for explicit operator recovery. No
historical workspace was inspected or changed.

No credential was read and no provider attempt, live v2 run, artifact,
failure, or charge was created.
