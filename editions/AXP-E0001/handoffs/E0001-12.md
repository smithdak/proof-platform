# E0001-12 Handoff

Result: blocked at the task's explicit stop condition; no product code changed

## Exact blocker

The bundled SQLite Unix VFS cannot combine the two required properties without
another VFS boundary:

1. Linux exposes an owned directory descriptor to pathname-only APIs as
   `/proc/self/fd/<fd>/<leaf>`. The `<fd>` component is a procfs magic symbolic
   link.
2. SQLite's `unixFullPathname` resolves every symbolic-link component and
   returns `SQLITE_OK_SYMLINK` when it encountered any. With
   `SQLITE_OPEN_NOFOLLOW`, `sqlite3_open_v2` converts that result to
   `SQLITE_CANTOPEN_SYMLINK` before opening the database.
3. Omitting `SQLITE_OPEN_NOFOLLOW` is not an acceptable workaround. The same
   VFS canonicalizes `/proc/self/fd/<fd>/<leaf>` to the ordinary filesystem
   pathname. SQLite therefore does not retain the descriptor namespace for
   later WAL, shared-memory, journal, or delete operations. Merely retaining
   the Rust `File` cannot pin those later pathname resolutions after the
   directory is renamed or replaced.

This is not solvable with rusqlite's public connection constructors: they pass
only a filename and flags to SQLite. A correct implementation needs an
`openat`/directory-descriptor-aware VFS (or equivalent upstream SQLite support),
but E0001-12 explicitly forbids a custom VFS. A check-then-open pathname guard
would preserve neither atomicity nor sidecar pinning and was not implemented.

## Reproduction evidence

A disposable storage integration probe used a fresh `TempDir`, an owned
directory `File`, and the exact requested flags:

```text
Connection::open_with_flags(
    "/proc/self/fd/<fd>/proof.db",
    OpenFlags::default() | OpenFlags::SQLITE_OPEN_NOFOLLOW,
)
```

Observed result:

```text
SqliteFailure(Error { code: CannotOpen, extended_code: 1550 },
Some("unable to open database file: /proc/self/fd/3/proof.db"))
```

Extended code 1550 is `SQLITE_CANTOPEN_SYMLINK`. The control open without
`SQLITE_OPEN_NOFOLLOW` succeeded, but `PRAGMA database_list` returned the real
temporary-directory pathname rather than `/proc/self/fd/<fd>/proof.db`, proving
that SQLite canonicalized away the descriptor namespace. The disposable probe
was removed after the run.

Command/result:

- `rtk proxy cargo test -p proof-storage --test descriptor_probe -- --nocapture`
  — PASS as a diagnostic probe; reproduced both behaviors above.

## Required owner decision

Either authorize a narrowly reviewed descriptor-aware SQLite VFS as material
scope/security work, or revise the storage boundary. The current task contract
cannot be implemented faithfully. E0001-09 must remain blocked because an
ordinary path open or pre-open check would reintroduce the pre-key/database
TOCTOU that D-E0001-008 prohibits.

No migration content, cross-crate source, credentials, provider, network, live
workspace, commit, push, or reverse-impact suite was touched. Scoped storage
tests and formatting were not run because the required product implementation
stopped before source changes.
