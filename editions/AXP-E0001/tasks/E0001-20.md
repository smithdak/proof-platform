# E0001-20 — One-shot live start and secure operator recovery

- Wave: W15
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical credential-free security repair; no provider or consequence execution
- Dependencies: E0001-02, E0001-07, E0001-08, E0001-09, E0001-18, E0001-19

## Objective

Make the frozen live-v2 start globally one-shot, make every advertised
follow-up command exact and workspace-bound, and preserve same-run recovery
across process death without permitting concurrent resumers to poison the
immutable checkpoint history or orphan an authorized provider response.

## Required repair

1. Add a backward-compatible atomic live-start claim contract keyed by the
   exact readiness binding and stable setup. SQLite must commit the claim,
   initial Running run, checkpoint zero, and Started event zero in one
   transaction and exact-validate all four records on replay.
2. Make an exact or concurrent `live-start` replay return the original run
   without constructing a gateway, dispatching again, or allocating a
   replacement run. Conflicting readiness/setup pairs must fail before the
   provider boundary.
3. Recover a process death after the claim but before provider preparation
   only from the exact pristine run/checkpoint/event prefix, a fresh durable
   process epoch, zero counters/usage/cost, and no step, approval, evaluation,
   or later event evidence.
4. Emit only array-form, workspace-bound review/decision/recovery/watch argv.
   Bind live-v2 approval persistence to the exact five arguments, sealed
   request/step, required Human, and policy-bearing `live-resume`; advertise
   neither generic resume nor the current approval UI.
5. Publish one secure live-v2 operator runbook and mark the legacy preview
   provider gate superseded. The runbook must use the retained packet's exact
   persisted start argv, same-run recovery, stop rules, redaction, and
   credential-free terminal replay.
6. Enforce one active live execution writer with a crash-released lease from
   before resume reads through return. Add backward-compatible atomic
   expected-tail checkpoint append in Kernel and SQLite, prevalidate the full
   prospective live history, and bind resume epochs to the exact prior state.
   Resume contention and stale checkpoint writers must perform zero writes;
   start contention may retain only its atomic four-record claim bundle. No
   contention path may perform a post-claim write, gateway construction,
   provider send, or governed effect.

## Non-goals

No credential read, provider construction, live run, Human decision,
publication, artifact, policy/registry/schema change, historical workspace
inspection, or Gate C decision. Do not reproduce private argv or signing
material in edition records.

## Acceptance

- Kernel and storage claim contracts are backward-compatible; SQLite
  migration 13 and claim/tamper/concurrency round trips pass.
- Runtime exact and concurrent start replay performs one run and one dispatch;
  injected post-claim failure resumes that same pristine run with one dispatch.
- Concurrent pristine and shared-Prepared resumes select one execution writer;
  the loser is read-only, a crash releases ownership, stale epoch/ordinary
  writes cannot append, and the surviving history remains replayable with one
  provider send.
- Acquired-start contention retains exactly the atomic initial claim bundle,
  performs no dispatch, and exact persisted-start replay followed by emitted
  same-run recovery reaches one provider send after lease release.
- Recording and two-connection SQLite expected-tail tests cover append,
  displaced writers, exact retry/currentness, malformed candidates, corrupt
  current/predecessor evidence, and zero-write history preservation.
- Wrong-Human and substituted approval evidence persist zero decisions, and
  live output exposes exact workspace/policy/Human argv plus the five reviewed
  publication arguments.
- Runtime, CLI, kernel, storage, reverse-impact, formatting, diff, and edition
  validation gates pass at final source.
- Independent runtime/recovery, CLI/security, and operator-runbook audits pass.
- With both provider variables removed, the retained readiness packet replays
  exactly 10/10 with unchanged binding digest, ready-record SHA-256, private
  modes, and persisted `next_argv`.

## Stop and escalate

Stop before provider construction on an unsupported store, claim conflict,
inexact bootstrap prefix, ambiguous attempt, wrong workspace/Human/policy,
reconstructed argv, readiness drift, missing retained packet, or any need to
read a credential. Preserve all durable evidence.

## Handoff

Record the claim/replay/recovery invariants, CLI/runbook constraints, exact
test and audit results, readiness identifiers/digests, and remaining
credential boundary. Never record credentials, private keys, copied databases,
raw provider bodies, or complete `.proof` data.
