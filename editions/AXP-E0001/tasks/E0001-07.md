# E0001-07 — Scoped delegation persistence

- Wave: W2
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical migration/authority path; approved Gate B required
- Dependencies: E0001-01

## Objective

Make SQLite the authoritative, lossless `ExecutionStore` source for bounded
delegation grants by appending the approved scope migration and implementing
`SqliteStore::load_delegation` with fail-closed parsing and round-trip tests.

## Writable paths (exclusive)

- `crates/proof-storage/**`
- `editions/AXP-E0001/handoffs/E0001-07.md`

## Read-only references

- Approved E0001 contract, migration decision, and E0001-01 handoff
- Kernel delegation and `ExecutionStore` contracts
- CLI's existing delegation SQL as a downstream consumer

## Non-goals

No kernel, CLI, runtime, Content, existing-migration edit, permissive fallback,
or live workspace/provider use.

## Acceptance

- A new migration uses the next sequential version and preserves legacy rows
  with the contract's explicit backward-compatible scope representation.
- `SqliteStore::load_delegation` returns the complete grant, including
  operation/domain/resource scope, and returns `None` only for an unknown ID.
- A storage-local strict representation rejects unknown `scope_json` keys;
  only the frozen `DelegationScope` keys are accepted. Invalid UUID, principal,
  JSON, time, or scope data fails closed and never becomes an unbounded default
  grant.
- Round-trip integration tests cover exact bounded scope, known optional
  resource scope, E0001 resource-scope rejection, legacy compatibility,
  revocation, missing ID, malformed/unknown-key scope, and migration
  upgrade/rollback rules.
- `rtk cargo fmt --check -p proof-storage` passes.
- `rtk cargo test -p proof-storage` passes.
- `rtk scripts/test-scoped.sh proof-storage` passes after W2 quiesces.

## Stop and escalate

Stop if the frozen representation cannot preserve legacy data safely, needs a
kernel type change, or conflicts with another migration version. Never edit or
renumber an existing migration.

## Handoff

Record migration number/SQL, serialized scope shape, load semantics,
round-trip/corruption/rollback evidence, commands/results, and residual risks.
