# E0001-10 — Runtime check-only live setup validation

- Wave: W5
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical live-run creation and credential boundary
- Dependencies: E0001-02, E0001-08

## Objective

Expose one additive runtime-owned, credential-free check API for a proposed
`LiveRunSetup::Start`. It must execute the same authoritative setup,
persisted-preflight, authority, policy, target-AgentDefinition, goal, identity,
and limit validation used immediately before `run_live` creates a live run,
while performing no mutation and never invoking a gateway factory.

## Writable paths (exclusive)

- `crates/proof-agent-runtime/**`
- `editions/AXP-E0001/handoffs/E0001-10.md`

## Read-only references

- Approved E0001 contract/policy and D-E0001-004 through D-E0001-006
- E0001-02 and E0001-08 handoffs
- E0001-09 task and current CLI `start_setup` construction

## Required API

- Add a clearly named public method such as
  `AgentRuntime::check_live_start_setup(&LiveRunSetup)`.
- It accepts only `LiveRunIntent::Start`; resume intent fails specifically.
- It calls the existing authoritative `validate_live_setup`, loads the exact
  target live AgentDefinition, and calls the existing
  `validate_live_agent` with the exact goal and prospective 300-second
  authority deadline.
- `run_live` start uses this same public path before `start_live`.
  `start_live` retains its timestamp-selected revalidation immediately before
  the first run write to close the authority-validity race.

## Non-goals

No contract/policy/schema/migration/CLI/Content/storage/kernel edit, provider
construction, credential/environment access, run creation, checkpoint/event/
step/evaluation/effect write, validation weakening, live attempt, commit, push,
or reverse-impact suite.

## Acceptance

- A complete valid frozen setup passes and leaves all run, checkpoint, event,
  step, evaluation, approval-execution, effect, and provider-attempt stores
  byte/count identical.
- Gateway-factory construction and send spies remain zero on valid and invalid
  checks.
- Invalid preflight evidence/evaluation, authority/delegation, policy/static
  digest, process/idempotency ID, approver, agent provider/model/tool/limits,
  target agent ID, goal, identity, and resume intent fail before any mutation.
- Tests prove check-only and `run_live` share the same authoritative validators
  rather than duplicating a weaker implementation.
- Existing live start/resume/replay and generic runtime behavior remain green.
- `rtk cargo fmt --check -p proof-agent-runtime` passes.
- `rtk cargo test -p proof-agent-runtime --locked` passes.
- `rtk scripts/test-scoped.sh proof-agent-runtime` passes only after W5
  quiesces under the orchestrator.

## Stop and escalate

Stop if the method cannot remain read-only, requires exposing private runtime
state, changes the frozen validator semantics, or needs another crate edit.
Return the exact blocker; do not create a sacrificial run or factory failure to
simulate check-only behavior.

## Handoff

Record the exact public API, validator reuse, no-mutation/factory evidence,
negative cases, commands/results, and residual risks. Do not include
credentials, private key material, or workspace/database copies.
