# E0001-14 — Delegation principal identity integrity

- Wave: W9
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical credential-free authority repair; no new live-use authority
- Dependencies: E0001-09

## Objective

Repair the CLI delegation grant path so it cannot mutate the durable kind or
public key of the workspace Agent or an existing recipient. Preserve the
retained E0001 readiness packet and fail before delegation persistence on any
principal identity collision.

## Writable paths (exclusive)

- `crates/proof-transport-cli/src/commands/delegation.rs`
- `editions/AXP-E0001/handoffs/E0001-14.md`

## Read-only references

- `contracts/kernel-api.md` principal persistence contract
- E0001-08 and E0001-09 task/handoff authority evidence
- `SqliteStore::save_principal` immutable identity behavior
- The retained fresh E0001 readiness record and narrow principal-kind facts;
  never private keys or credential values

## Required repair

1. Persist the issuer from the actual workspace keypair principal; never
   hard-code a Human issuer for an Agent workspace.
2. When a delegation recipient already exists, require the same durable kind
   and any supplied public key. Return a specific conflict without updating
   kind, display name, or key.
3. Preserve the existing absent-recipient Agent placeholder behavior for CLI
   compatibility; do not redesign enrollment or delegation storage here.
4. Perform principal validation before saving the delegation.
5. Add regressions for a distinct recipient and an already enrolled Human
   recipient, including unchanged immutable identity and zero failed-grant
   delegation rows.

## Non-goals

No kernel/storage schema or API change, recipient enrollment redesign, signed
revocation redesign, runtime/Content/HTTP edit, provider credential read,
network/live call, readiness regeneration, historical workspace use, or
private-key inspection.

## Acceptance

- The workspace issuer remains the exact same Agent ID, kind, and public key
  after granting to a distinct recipient.
- An existing Human recipient is rejected as a kind collision, remains exact,
  and creates no delegation.
- Existing same-actor and legacy-scope delegation tests remain green.
- All CLI test targets compile; focused delegation tests pass.
- `rtk cargo fmt --check -p proof-transport-cli` and scoped diff checks pass.
- Because the managed sandbox rejects the crate's intentional loopback and
  trusted-root tests, a full locked CLI replay in host context is a mandatory
  E0001-04 entry check before provider construction.

## Stop and escalate

Stop on a required shared/storage contract change, any need to weaken identity
immutability or secure-path checks, a credential boundary, retained packet
mutation, or new live/provider evidence.

## Handoff

Record the original mutation path, exact repair, regression results, retained
packet identity facts, environment-limited full-suite result, and the host
replay barrier. Never record a credential, private key, or copied database.
