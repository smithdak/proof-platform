# E0001-06 — Version-aware kernel execution boundary

- Wave: W2
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical shared API; approved E0001-01 Gate B contract required
- Dependencies: E0001-01

## Objective

Implement the frozen, default-compatible `OperationHandler` version hooks so
one operation name can preserve v1 behavior while v2 selects exact replay and
its own handler path. Prove the explicit delegation-ID execution path enforces
the stored grant's operation/domain scope without weakening existing authority.

## Read-only references

- Approved E0001 contract, policy, decision, and E0001-01 handoff
- `contracts/kernel-api.md`, `contracts/domain-definitions.md`
- Existing execution, replay, approval, and delegation tests

## Non-goals

No shared struct field, error variant, proof format, migration, storage,
transport, Content implementation, or global authority-semantics change beyond
the explicitly approved contract.

## Acceptance

- Existing handlers compile unchanged and retain current `idempotency_policy`
  and `execute` behavior through default methods.
- Engine dispatch passes the registry version to both version-aware hooks;
  tests prove v1 and v2 of one operation choose different replay/execute paths.
- Authorization, governance, lifecycle, approval, delegation, replay claim,
  handler entry, evidence, and replay completion retain their approved order.
- Tests prove an explicit `delegation_id` must resolve to the matching stored
  grant and rejects an out-of-scope operation/domain before handler entry.
- `rtk cargo fmt --check -p proof-kernel` passes.
- `rtk cargo test -p proof-kernel` passes.
- `rtk scripts/test-scoped.sh proof-kernel` passes after W2 quiesces.

## Stop and escalate

Stop on a required shared type/error change, a transport mapping, a breaking
handler API, proof/replay format drift, or a request to silently outlaw an
existing chain-only caller. Return the bounded integration request.

## Handoff

Record API signatures, compatibility evidence, execution order, authority and
version/replay tests, commands/results, downstream impact, and residual risks.
