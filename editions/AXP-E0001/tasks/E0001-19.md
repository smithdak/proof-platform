# E0001-19 — Live-v2 approval review visibility

- Wave: W14
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: high credential-free security repair; no provider or consequence execution
- Dependencies: E0001-02, E0001-08, E0001-18

## Objective

Make the exact live-v2 pending consequence inspectable through the existing
human approval review surface before a decision can be signed, while keeping
malformed, mixed-version, stale, or digest-substituted checkpoint evidence
non-actionable.

## Writable paths (exclusive)

- `crates/proof-agent-runtime/**`
- `crates/proof-transport-cli/**`
- `editions/AXP-E0001/handoffs/E0001-19.md`

## Required repair

1. Add one runtime-owned, typed projection from supported v1/v2 runtime
   checkpoints to the common pending-approval fields. The input must be the
   complete contiguous history from sequence zero with one exact supported
   version and strict checkpoint envelopes.
2. Keep diagnostic state viewing separate from approval actionability. `agent
   watch` must expose typed v2 Dispatching/Committed crash-window checkpoints
   even when their causal event was not durable yet; it must not make them
   actionable.
3. Bind live-v2 approval projection to the exact committed response event,
   call ID, typed arguments, sealed signed request, reconstructed durable
   waiting step, and exact policy-bound Human approver.
4. Make the approval UI fail closed on unsupported/mixed history, omitted
   prefixes, malformed envelopes, request/step/call/argument substitution, or
   a missing/wrong Human. A v2 decision must never recommend generic `agent
   resume`; only the exact policy-bearing `live-resume` path is valid.
5. Preserve v1 behavior and prove the v2 path through real SQLite history,
   runtime validation, review construction, detail rendering, and decision
   routing.

## Non-goals

No provider construction, credential read, live run, approval signature,
publication, policy/schema/registry change, generic checkpoint migration, or
new approval authority. Raw checkpoint data alone never makes a request
actionable.

## Acceptance

- A valid real-SQLite live-v2 history renders the five exact publication
  arguments and is actionable only when its embedded and persisted
  Agent-signed request, durable waiting step, committed call, and sealed Human
  approver are exact.
- Invalid v2 state, mixed v1/v2 runtime history, unsupported runtime versions,
  omitted sequence-zero history, wrong run/agent/step/request/call, or
  substituted arguments are visibly blocked before approval or effect.
- Valid Dispatching and Committed crash-window checkpoints remain visible in
  `agent watch` without depending on events that may not yet exist.
- A live-v2 approval response contains no generic resume command.
- Existing v1 approval UI behavior remains green.
- Scoped Runtime and CLI tests, crate formatting, diff checks, edition
  validation, full host CLI gate, and exact credential-free readiness replay
  pass before E0001-04 may start.

## Stop and escalate

Stop on any need to weaken the signed digest, accept raw unvalidated v2 state,
change live policy or consequence values, read a credential, create a live run,
or mutate the retained readiness workspace.

## Handoff

Record the visibility gap, projection and fail-closed invariants, exact tests,
host/readiness results, and residual limitations. Never record credentials,
private keys, copied databases, or historical `.proof` data.
