# E0001-12 — Descriptor-pinned nofollow SQLite open

- Wave: W6
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical pre-key/database symlink boundary
- Dependencies: E0001-07, E0001-10

## Objective

Add one storage-owned SQLite open seam for a caller-supplied, already opened
directory descriptor and strict single-component database name. The connection
must atomically reject a symbolic-link database leaf, keep the directory
descriptor alive for SQLite main/WAL/journal sidecar semantics, and remain
pinned to that directory if pathname entries are renamed or replaced.

## Writable paths (exclusive)

- `crates/proof-storage/**`
- `editions/AXP-E0001/handoffs/E0001-12.md`

## Read-only references

- E0001-07/09 tasks and handoffs
- rusqlite `OpenFlags::SQLITE_OPEN_NOFOLLOW` and current `SqliteStore::open`
- Existing SQLite migration and round-trip tests

## Required API

- Add a narrow Linux implementation such as
  `SqliteStore::open_nofollow_in_directory(File, &str)`; unsupported targets
  fail closed with a specific error.
- Validate the owned descriptor is a directory and the database name is one
  ordinary component with no slash, backslash, dot/dot-dot, NUL, URI/query, or
  traversal syntax.
- Open through the pinned descriptor namespace using
  `OpenFlags::default() | SQLITE_OPEN_NOFOLLOW`; retain the directory
  descriptor inside `SqliteStore` for the full connection lifetime.
- Preserve the existing WAL, foreign-key, and migration initialization. Keep
  existing `SqliteStore::open` and in-memory callers backward compatible.

## Non-goals

No CLI/runtime/kernel/Content/contract/migration-content edit, custom SQLite
VFS, key/config read, credential/provider/live call, weakened existing open,
commit, push, or reverse-impact suite.

## Acceptance

- A regular database in a pinned private directory opens, migrates, writes,
  reads, checkpoints WAL, and reopens with normal round-trip behavior.
- A symbolic-link database leaf is rejected atomically and its target bytes/
  schema remain untouched.
- Renaming/replacing the directory pathname after its descriptor is opened
  cannot redirect the connection or its sidecars; evidence stays in the
  descriptor-pinned original directory.
- Traversal/multicomponent/URI-like names and non-directory descriptors fail
  before SQLite creates or mutates a file.
- Existing open/in-memory/migration tests remain green.
- `rtk cargo fmt --check -p proof-storage` passes.
- `rtk cargo test -p proof-storage --locked` passes.
- `rtk scripts/test-scoped.sh proof-storage` passes only after W6 quiesces
  under the orchestrator.

## Stop and escalate

Stop if rusqlite/SQLite cannot preserve WAL/journal semantics through the
pinned directory, if the database leaf can still follow a symlink, or if a
custom VFS/another crate is required. Return the exact blocker; do not accept a
check-then-open pathname guard.

## Handoff

Record API/flags, descriptor lifetime, main/WAL/journal paths, symlink/
rename/traversal tests, commands/results, platform behavior, and residual
risks. Do not include workspace/database copies, credentials, commits, or
pushes.
