# E0001-15 — Workspace import identity and authority integrity

- Wave: W10
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical credential-free authority repair; no new live-use authority
- Dependencies: E0001-14

## Objective

Repair the CLI workspace import path so an archive cannot replace an enrolled
principal's immutable kind or public key, replace or un-revoke an existing
delegation ID, or persist imported identity/proof data before every proof
signature has passed validation.

## Writable paths (exclusive)

- `crates/proof-transport-cli/src/commands/transfer.rs`
- `crates/proof-transport-cli/src/main.rs`
- `editions/AXP-E0001/handoffs/E0001-15.md`

## Read-only references

- `contracts/kernel-api.md` principal persistence contract
- E0001-14 task/handoff authority evidence
- `SqliteStore::save_principal` immutable identity behavior
- Existing workspace export/import compatibility tests

## Required repair

1. Decode and validate every exported principal key, reject duplicate IDs, and
   compare any enrolled principal's durable kind and public key before import.
2. Use the canonical immutable principal storage API; remove the import-only
   conflict update that rewrites identity.
3. Reject duplicate delegation IDs, invalid validity windows, missing
   principals, and any imported delegation that differs from an existing
   durable grant with the same ID. Recheck equality in an immediate atomic
   conditional write so a concurrent change cannot be overwritten; exact
   replay remains idempotent.
4. Verify every imported proof against an enrolled or preflighted principal
   before persisting any archive principal, proof, or delegation.
5. Add regressions for kind/key replacement, delegation unrevocation, and an
   invalid proof that leaves its imported principal and proof absent.

## Non-goals

No archive-format, kernel/storage schema, public API, global delegation storage,
signed-revocation, provider, runtime, Content, HTTP, historical-workspace, or
retained-readiness change. Full transactional import of blobs, registry, and
workspace files remains outside this bounded authority repair.

## Acceptance

- Kind and key collisions fail before archive principal/proof/delegation writes
  and leave the enrolled identity exact.
- An archive cannot replace or un-revoke an existing delegation ID; the stored
  grant remains exact, while exact replay succeeds idempotently.
- A valid proof preceding an invalid signature remains unpersisted, as does its
  previously absent imported principal.
- Normal export/import round-trip and newer-existing-proof behavior remain
  green.
- All CLI test targets compile; focused import tests pass.
- `rtk cargo fmt --check -p proof-transport-cli` and scoped diff checks pass.
- The managed sandbox's loopback and synthetic-root failures are isolated, the
  complete suite passes in host context, and no security check is weakened.

## Stop and escalate

Stop on a required shared/storage contract change, archive-format migration,
need to weaken immutable identity or secure-path checks, credential boundary,
retained packet mutation, or provider/live evidence.

## Handoff

Record the original mutation/partial-write paths, exact preflight repair,
regression and compatibility results, remaining non-atomic import scope, and
the host replay result. Never record a credential, private key, or copied
database.
