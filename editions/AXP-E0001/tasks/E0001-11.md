# E0001-11 — Runtime bootstrap crash reconciliation

- Wave: W6
- Model/reasoning: `gpt-5.6-sol` / high
- Risk and owner gate: critical duplicate-run/tool-effect recovery boundary
- Dependencies: E0001-02, E0001-10

## Objective

Make the generic `AgentRuntime::start` bootstrap durably recoverable through
public `resume` when a process dies after the run is saved but before the
initial checkpoint or exact Started event. Recovery must adopt only the unique
existing run selected by its caller and may never create a replacement run,
fabricate later evidence, or dispatch before the initial state/event barriers
are exact and durably reread.

## Required behavior

- Refactor the initial generic state construction and exact Started-event
  barrier into runtime-owned helpers shared by `start` and `resume`.
- `resume(run_id)` may repair only an exact bootstrap state produced by
  `start`: the expected actor, agent, Session mode, nonempty saved goal,
  retry count, revision/status chronology, and no conflicting step,
  checkpoint, evaluation, approval execution, or event evidence.
- A pristine saved Queued run is transitioned once to Running and saved. A
  pristine Running run without a checkpoint gets the exact initial
  `AgentRuntimeState` derived from its durable run/agent timestamps and goal.
- A valid initial checkpoint without Started gets the exact Started event.
  Existing exact state/event is reread and reused; duplicates, later events,
  steps, evaluations, mismatched state, or impossible chronology fail closed.
- Only after the exact initial checkpoint and Started event are both present
  and reread may normal `drive` continue. Existing Waiting/terminal recovery
  behavior remains unchanged.

## Non-goals

No CLI/Content/storage/kernel/contract/schema/migration edit, caller-authored
run/step/event/checkpoint row, replacement run, ambiguous provider retry,
validation weakening, credential/provider/live call, commit, push, or
reverse-impact suite.

## Acceptance

- Deterministic fault-injection tests stop after: initial Queued save, Running
  save, initial checkpoint save, and Started event save. Public `resume`
  returns the same run ID and completes/pauses normally with exactly one
  initial checkpoint and Started event.
- Repeating resume after every repair boundary is idempotent and cannot append
  another bootstrap checkpoint/event or execute a tool twice.
- Corrupt/mismatched actor, agent, mode, goal/state, revision/timestamps,
  duplicate checkpoint/event, non-Started event, step, evaluation, or approval
  evidence fails before gateway or tool dispatch.
- Factory/gateway/tool spies remain zero until both bootstrap barriers reread
  exactly; no recovery path creates a second run.
- Existing generic, approval, terminal, live-start, live-resume, and sealed
  replay tests remain green.
- `rtk cargo fmt --check -p proof-agent-runtime` passes.
- `rtk cargo test -p proof-agent-runtime --locked` passes.
- `rtk scripts/test-scoped.sh proof-agent-runtime` passes only after W6
  quiesces under the orchestrator.

## Stop and escalate

Stop if recovery cannot distinguish a pristine start bootstrap from ambiguous
later work, needs another crate/API contract, or would retry a possibly
dispatched provider/tool effect. Preserve the partial run as evidence and
return the exact blocker.

## Handoff

Record shared helpers, accepted/rejected partial states, exact-one barrier
evidence, fault-injection commands/results, and residual risks. Do not include
credentials, private keys, workspace/database copies, commits, or pushes.
