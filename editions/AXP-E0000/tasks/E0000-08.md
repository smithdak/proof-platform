# E0000-08 — Deterministic Release Manager automation

Model: `gpt-5.6-terra` · reasoning: `medium`

## Objective

Harden the deterministic Release Manager fixture and evaluation so repeated
runs prove approval pause/resume, exact tool arguments, signed evidence, and a
stable trace digest.

## Writable paths (exclusive)

- `docs/dogfood/release-manager-preview.md`
- `evals/release-manager-preview-v1.json`
- `crates/proof-agent-runtime/**`
- `editions/AXP-E0000/handoffs/E0000-08.md`

## Read-only references

`AGENTS.md`, `ARCHITECTURE.md`, current dogfood doc, runtime crate tests,
`contracts/**`, registry release operation.

## Dependencies

E0000-07. Live-provider execution is not required for this deterministic item.

## Risk and owner gate

Medium/high evidence risk; runtime owner and orchestrator review evaluation
policy changes.

## Non-goals

Do not add provider credentials, print secrets, require network access, or claim
that deterministic evidence proves live model quality.

## Acceptance

1. `rtk rg -n '10 checks|trace digest|approval_resumed|release.publish::v1' docs/dogfood/release-manager-preview.md evals/release-manager-preview-v1.json` finds required assertions.
2. `rtk cargo test -p proof-agent-runtime` passes for changed runtime fixtures.
3. `rtk cargo fmt --check -p proof-agent-runtime` passes.
4. `rtk git diff --check -- docs/dogfood evals crates/proof-agent-runtime editions/AXP-E0000/handoffs/E0000-08.md` passes.
5. One executable test constructs two independent Release Manager fixtures
   from the same fixed deterministic inputs and evaluates the checked-in
   `evals/release-manager-preview-v1.json` policy directly. Both runs produce
   the same trace digest, score 10/10, contain `approval_resumed`, and have no
   failed checks/events. Do not weaken production trace binding by excluding
   durable run, proof, event, or identity fields merely to make random fixtures
   compare equal.

## Stop/escalate

Stop if fixture changes need production runtime edits, credentials, or a live
provider; escalate to the orchestrator and owner.

## Handoff schema

Report: fixture command; run/evaluation IDs; trace digests; approval chronology;
policy changes; limitations; risks; live-gate follow-up.
