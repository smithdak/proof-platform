# E0000-15 — Idempotency transport error mapping

Model: `gpt-5.6-luna` · reasoning: `medium`

## Objective

Add exhaustive HTTP and WebSocket mappings/tests for the frozen idempotency
errors without changing operation routing or other peer behavior.

## Writable paths (exclusive)

- `crates/proof-transport-http/**`
- `crates/proof-transport-ws/**`
- `editions/AXP-E0000/handoffs/E0000-15.md`

## Read-only references

D-E0000-006, E0000-13, the frozen proof-kernel error variants, and existing
transport error tests.

## Dependencies

E0000-13 and explicit Gate B approval of D-E0000-006. It may run concurrently
with E0000-14 and E0000-16 against the frozen error interface.

## Risk and owner gate

High; mappings must remain exact: input errors 400, conflicts 409, durable
storage required 503, and storage corruption 500.

## Non-goals

No kernel, storage, content, registry, routing, or unrelated transport changes.

## Acceptance

1. HTTP exhaustive mapping and tests cover every idempotency variant.
2. WebSocket exhaustive mapping and tests use invalid-input, stable conflict,
   and storage/internal classes as approved.
3. `rtk cargo fmt --check -p proof-transport-http` and
   `rtk cargo fmt --check -p proof-transport-ws` pass.
4. `rtk cargo test -p proof-transport-http` and
   `rtk cargo test -p proof-transport-ws` pass.

## Stop/escalate

Stop on error-interface drift or any need to edit another crate.

## Handoff schema

Report: mappings; files; tests; interface assumptions; residual requests.
