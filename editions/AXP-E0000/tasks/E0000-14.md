# E0000-14 — Kernel exact-replay API and engine

Model: `gpt-5.6-sol` · reasoning: `high`

## Objective

Implement the owner-approved E0000-13 kernel design so exact retries
return the original output and signed proof and conflicting reuse fails before
domain mutation.

## Writable paths (exclusive)

- `crates/proof-kernel/**`
- `editions/AXP-E0000/handoffs/E0000-14.md`

## Read-only references

Approved D-E0000-006, frozen content v1 contract, transport error mappings, and
existing execution/approval persistence tests.

## Dependencies

E0000-13 and explicit owner Gate B approval of D-E0000-006.

## Risk and owner gate

Critical; do not start while the migration/API decision is pending.

## Non-goals

No storage implementation/migration, content handlers, registry/schema edits,
transport changes, or contract expansion.

## Acceptance

1. Every new public function has a kernel unit test.
2. Exact retry returns byte-equivalent output and the same proof ID/signature.
3. Same scoped key with different canonical input fails before handler entry.
4. Concurrent claims cannot execute the mutation twice; failed attempts do not
   become completed replay records and have a defined recovery path.
5. `rtk cargo fmt --check -p proof-kernel` passes.
6. `rtk cargo test -p proof-kernel` passes; the handoff records
   `rtk scripts/test-scoped.sh proof-kernel --list` for integration.

## Stop/escalate

Stop on any public-contract change, new unapproved migration shape, transport
edit, or cross-owner requirement.

## Handoff schema

Report: files; API; engine lifecycle; tests; cross-owner requests; downstream
impact and residual risks.
