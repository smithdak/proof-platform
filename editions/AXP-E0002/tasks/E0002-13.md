## Acceptance

- Strict versioned shapes reject unknown/duplicate fields and bind Human,
  workspace, server instance, capabilities, revisions, filters, cursor, command
  idempotency key, fence epoch, budgets, and audit linkage.
- The auth contract defines a fresh E0002 signed challenge and one-use issuance
  flow rooted in an enrolled Human. It binds nonce, instance, workspace,
  requested/granted capability intersection, expiry, and replay protection; it
  imports no E0006 bootstrap/session authority.
- Exact loopback launcher/listener/startup/shutdown, signed-challenge credential
  delivery, same-origin UI/API assembly, session self-revoke, expiry, and
  control-plane crash/restart behavior are normative rather than left to the
  implementation.
- One authoritative workspace database, trusted-open policy, migration 14,
  signer/key lifecycle, and fresh disposable identity boundary are normative.
  CLI/MCP versus HTTP/WS path drift and the compromised repository-root
  `.proof` identity cannot be inherited silently.
- Public adapter boundaries let the W4 control shell accept synthetic
  store-opener/router implementations without depending on in-progress W4
  storage/runtime source. The frozen dependency direction is acyclic: the HTTP
  crate exports a protected router without importing the control crate, and
  E0002-15 later binds HTTP/storage/runtime into the control process. E0002-14
  owns real backend conformance composition, not runnable source assembly.
- The dedicated operator router enumerates every mounted route and excludes or
  authenticates all legacy audit, proof, domain-list, and generic operation
  surfaces before lookup. Forwarded-client metadata is never an authority or
  session boundary.
- Auth and capability checks precede enumeration, signing-key load, provider or
  tool dispatch, state mutation, and distinguishable not-found/conflict data.
- Exact capabilities include `run.read`, `approval.read`, `approval.decide`,
  `run.cancel`, `run.resume`, and `audit.read`; session revoke is not conflated
  with run cancel, approval denial, delegation revoke, or decision withdrawal.
- Approval never resumes automatically. Cancel/resume/expiry/recovery races,
  uncertain responses, keyset pagination, append-only events, fenced leases,
  and aggregate budgets have one normative ordering.
- Separate required vectors cover `runtime_worker_restart` while the
  control-plane instance/session remains live and `control_plane_restart`,
  which invalidates all volatile authority and requires fresh authentication.
- Approval signing requires the authenticated Human to match the sealed
  required Human unless Gate B explicitly freezes a narrower delegation policy;
  merely requesting `approval.decide` cannot select another Human's key.
- The evaluator is all-required, has frozen ordered checks and rejection
  vectors, and proves zero unauthorized effect with deterministic fixtures.
- Exact SHA-256 digests, proposed dependency/root-manifest delta, migration 14
  plan, rollback, limitations, and owner Gate B accept/reject text are recorded
  in the handoff; no implementation task is activated.
- The error contract either introduces no new global `ExecutionError` variant
  in W3 or assigns its exhaustive HTTP mapping and tests to that same wave;
  reporting a later transport need is not sufficient.
- After drafting, E0002-13 remains `review` and MUST NOT become `done` unless

  material-risk choices. Revision/rejection keeps W3 pending.
