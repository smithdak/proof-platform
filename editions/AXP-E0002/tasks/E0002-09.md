## Acceptance

- Mutation bodies bind exact Human/session, workspace/instance, capability,
  target, expected revision, idempotency key, requested outcome, and required
  Human before protected work.
- Auth/expiry/revoke races linearize with signing-key access and durable writes;
  losing authority causes no key load, signature, command, provider/tool work,
  or target-existence disclosure.
- Approval and denial persist exactly one signed decision and never resume.
  Resume is a separate explicit command. Decision, cancel, resume, and the
  E0002-11 session revoke remain distinct request shapes, confirmations,
  receipts, and audit events.
- Deterministic races cover approve/deny, decide/expiry, cancel/dispatch,
  cancel/resume, duplicate/lost response, stale revision/fence, and restart.
  Retrying an idempotency key returns the same receipt, never a second effect.
- The real backend-integration evidence from E0002-14 is reproduced for every
  mutation adapter boundary; no route substitutes transport-local status-only
  cancellation or an alternate database.
- Every endpoint has Tower oneshot tests for success, auth, scope, ordering,
  conflicts, uncertain-response readback, and exact headers.

  `rtk cargo test -p proof-transport-http`, and
  `rtk scripts/test-scoped.sh proof-transport-http` pass.
